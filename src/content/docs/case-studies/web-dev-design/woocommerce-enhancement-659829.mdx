## 1. Executive Summary

Many WooCommerce storefronts suffer from high bounce rates and cart abandonment due to sluggish server response times during product filtering and checkout. This friction rarely stems from server hardware limitations; instead, it is driven by unindexed queries in `wp_options` (expired transients), `wp_usermeta` bloat, and conflicting plugins exhausting PHP memory limits.

This blueprint presents a non-destructive staging isolation methodology to restore ecommerce speed with zero risk of transaction loss.

## 3. Standalone Diagnostic Script (wc_health_audit.php)

The following lightweight diagnostic script profiles PHP memory allocations, environment versions, and autoload options accumulation:

```php
<?php
/**
 * WooCommerce Health & Performance Auditor (Stand-Alone Diagnostics)
 * Non-destructive audit for WooCommerce environments.
 */

define('WP_USE_THEMES', false);
if (file_exists(__DIR__ . '/wp-load.php')) {
    require_once __DIR__ . '/wp-load.php';
}

$audit_results = [
    'timestamp'       => gmdate('Y-m-d\TH:i:s\Z'),
    'php_version'     => phpversion(),
    'memory_limit'    => ini_get('memory_limit'),
    'max_exec_time'   => ini_get('max_execution_time'),
    'active_plugins'  => [],
    'autoload_size_kb'=> 0,
];

if (function_exists('get_plugins')) {
    global $wpdb;
    $autoload_size = $wpdb->get_var("SELECT SUM(LENGTH(option_value)) FROM {$wpdb->options} WHERE autoload = 'yes'");
    $audit_results['autoload_size_kb'] = round($autoload_size / 1024, 2);
    $audit_results['active_plugins']   = get_option('active_plugins', []);
}

header('Content-Type: application/json');
echo json_encode($audit_results, JSON_PRETTY_PRINT);
```

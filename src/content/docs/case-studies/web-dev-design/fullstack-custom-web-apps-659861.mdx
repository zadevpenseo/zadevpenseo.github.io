## 1. Executive Dilemma

Custom web engineering projects frequently destabilize under two flawed extremes:
1. *Monolithic Coupling:* Mixing business logic, presentation routing, and direct database queries inside single controller files without a domain service layer.
2. *Premature Over-Engineering:* Introducing distributed microservice overhead that inflates infrastructure overhead before product-market validation.

Our modular blueprint implements *Pragmatic Clean Architecture*: feature-driven directory structures, strictly indexed relational schemas, and idempotent API contracts.

## 3. Database Schema Blueprint (SQL DDL)

The following foundational schema establishes enterprise-grade relational data integrity:

```sql
-- Core Accounts & Profiles Schema
CREATE TABLE users (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    email VARCHAR(255) NOT NULL UNIQUE,
    password_hash VARCHAR(255) NOT NULL,
    role VARCHAR(50) NOT NULL DEFAULT 'member',
    is_active BOOLEAN NOT NULL DEFAULT TRUE,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE user_profiles (
    user_id UUID PRIMARY KEY REFERENCES users(id) ON DELETE CASCADE,
    display_name VARCHAR(150) NOT NULL,
    avatar_url TEXT,
    bio TEXT,
    preferences JSONB DEFAULT '{}'::jsonb
);

CREATE INDEX idx_users_email ON users(email);
```

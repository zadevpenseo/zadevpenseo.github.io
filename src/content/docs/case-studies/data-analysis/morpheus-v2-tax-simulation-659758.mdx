## 1. Problem Space: Floating-Point Tax Hazards

In commercial payroll and accounting systems, adopting standard computer `float` types creates compounding legal and financial liabilities:

```python
# IEEE 754 binary floating-point round-off hazards:
0.1 + 0.2 == 0.3  # Returns False (0.30000000000000004)
```

Across graduated statutory tax brackets and multi-tier withholdings, tiny fractional inaccuracies accumulate into substantial reconciliation discrepancies across balance sheets by fiscal year-end.

This blueprint delivers the Morpheus V2 statutory calculation engine operating strictly on arbitrary-precision decimal representations with configurable rounding modes.

## 3. Standalone Engine Implementation (morpheus_tax_engine.py)

```python
from decimal import Decimal, ROUND_HALF_UP

class MorpheusTaxEngine:
    def __init__(self, precision: str = "0.01"):
        self.precision = Decimal(precision)

    def round_currency(self, amount: Decimal) -> Decimal:
        return amount.quantize(self.precision, rounding=ROUND_HALF_UP)

    def calculate_progressive_tax(self, taxable_income: Decimal, brackets: list) -> dict:
        total_tax = Decimal("0")
        breakdown = []

        remaining = taxable_income
        for ceiling, rate in brackets:
            if remaining <= 0:
                break
            taxable_in_bracket = min(remaining, ceiling)
            tax_amount = taxable_in_bracket * rate
            total_tax += tax_amount
            remaining -= taxable_in_bracket

            breakdown.append({
                "taxable_amount": str(self.round_currency(taxable_in_bracket)),
                "rate": str(rate),
                "tax": str(self.round_currency(tax_amount))
            })

        return {
            "taxable_income": str(self.round_currency(taxable_income)),
            "total_tax": str(self.round_currency(total_tax)),
            "breakdown": breakdown
        }
```

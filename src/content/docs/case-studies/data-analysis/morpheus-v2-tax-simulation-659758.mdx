## 1. Problem Space: Floating-Point Tax Hazards

Dalam sistem penggajian dan akuntansi komersial, penggunaan tipe data `float` standar komputer adalah sebuah kesalahan fatal:

```python
# Bahaya binary floating point standar IEEE 754:
0.1 + 0.2 == 0.3  # Menghasilkan False (0.30000000000000004)
```

Pada simulasi pajak penghasilan berjenjang (*graduated tax brackets*) atau kalkulasi PPh 21, selisih pecahan terkecil akan menumpuk menjadi selisih audit ribuan rupiah di akhir tahun buku.

Cetak biru ini menyajikan mesin kalkulasi statutory Morpheus V2 yang beroperasi murni dengan aritmatika desimal dengan presisi yang dapat dikonfigurasi.

## 3. Implementasi Kode Mandiri (morpheus_tax_engine.py)

```python
from decimal import Decimal, ROUND_HALF_UP

class MorpheusTaxEngine:
    def __init__(self, precision: str = "0.01"):
        self.precision = Decimal(precision)

    def round_currency(self, amount: Decimal) -> Decimal:
        return amount.quantize(self.precision, rounding=ROUND_HALF_UP)

    def calculate_progressive_tax(self, taxable_income: Decimal, brackets: list) -> dict:
        total_tax = Decimal("0")
        breakdown = []

        remaining = taxable_income
        for ceiling, rate in brackets:
            if remaining <= 0:
                break
            taxable_in_bracket = min(remaining, ceiling)
            tax_amount = taxable_in_bracket * rate
            total_tax += tax_amount
            remaining -= taxable_in_bracket

            breakdown.append({
                "taxable_amount": str(self.round_currency(taxable_in_bracket)),
                "rate": str(rate),
                "tax": str(self.round_currency(tax_amount))
            })

        return {
            "taxable_income": str(self.round_currency(taxable_income)),
            "total_tax": str(self.round_currency(total_tax)),
            "breakdown": breakdown
        }
```

## 1. Problem Space: Unstructured PDF Tabular Chaos

Extracting multi-page financial transactions from PDF documents into relational Excel worksheets is traditionally error-prone:
- Multi-line transaction narratives collapse or spill across unintended rows and offset adjacent numeric columns.
- Numeric notations mix European/Indonesian formats (`1.000,00`) with Anglo-American standards (`1,000.00`), causing parse failures in standard spreadsheet tools.
- Public web-based converter SaaS tools introduce confidentiality leaks and compliance violations when handling proprietary client banking ledgers.

## 3. The Balance Reconciliation Invariant

Every account statement transformation enforces strict closed-loop accounting validation:

```python
from decimal import Decimal

def verify_statement_balance(
    opening_bal: Decimal, 
    debits: list[Decimal], 
    credits: list[Decimal], 
    closing_bal: Decimal
) -> bool:
    calculated_closing = opening_bal + sum(credits) - sum(debits)
    # Zero acceptable drift under exact Decimal arithmetic
    return calculated_closing == closing_bal
```

If any reconciliation discrepancy arises, even by a single cent, the engine halts export and flags the exact line coordinates for Human-in-the-Loop review.
